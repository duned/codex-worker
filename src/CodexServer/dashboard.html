Worker GitHub login

For the supported Server device flow, use Server GitHub connection in Settings. Worker authentication remains node-local. Choose Prepare GitHub login, then open a terminal on the target node as the service account. Complete the browser/device flow there. Keep device codes and tokens on the node. After login, choose Check authentication. This verifies node-local gh login only; provider-side scopes and repository read/write access are separate.

env -u GH_TOKEN -u GITHUB_TOKEN GH_CONFIG_DIR="$HOME/.local/share/codex-provisioning/github" gh auth login --hostname github.com --git-protocol ssh --web --skip-ssh-key

GitHub CLI uses its default credential storage. Setup refuses unrelated existing GitHub authentication configuration; use a dedicated service account with a secure credential store. Logout removes product authentication through gh; it does not revoke the token at GitHub. Existing operator authentication is preserved.

Repository SSH access

Generate a dedicated service-account key, then inspect its public key and fingerprint below and register it with GitHub. The private key remains on the node with mode 0600; the directory uses 0700. Establish a trusted github.com entry in the service account's known_hosts before verifying access. Verification reads the selected repository; it does not establish write permission. Existing SSH identities and configuration are preserved. Replacement requires explicit removal followed by generation. Git installation includes the OpenSSH client on supported Debian/Ubuntu nodes.

To use the key for execution, configure the checkout's repository-local core.sshCommand as the service account to use ssh -F /dev/null -o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -i "$HOME/.local/share/codex-provisioning/ssh/github_ed25519". Git identity (user.name and user.email) is configured separately on the node.
