# Managed interrupted retries

Fresh requests still require the project's ready label, an open Issue, no blocked label and no open dependencies. The Server assigns an exclusive lease; the Worker reports Claiming before replacing ready with working, then reports Preparing, Codex and Validation. The GitHub label alone is not ownership authority.

Lease expiry invalidates the original lease. Only attempts known to be before integration are requeued; Claiming, integration and uncertain completion remain protected for reconciliation. Each retry retains its previous execution ID and increments its attempt number. Repository/Issue reservations prevent assigning another live attempt for that identity, and lease generation checks fence stale reports and integration.

For a fresh-workspace retry, the Server generates `freshRecoveryExecutionId` only after verifying the immediate predecessor is failed with LeaseExpiredRequeued, an expired lease, a Preparing/Codex/Validation stage and no integration result, with unchanged project, work reference and consecutive attempt number. An unstarted assignment does not establish a consumed claim. This marker permits only the missing ready-label reason to be removed; all other eligibility reasons remain blocking. Closed Issues and dependencies continue to block. Accepted recovery emits `interrupted-recovery-accepted`; rejected eligibility is persisted in execution details and releases the assignment lease, leaving the request blocked until explicit refresh or corrective action.

The managed Worker uses its ordinary claim and execution pipeline with a fresh execution workspace regardless of configured local resume mode. It preserves old workspaces and history, and rejects conflicting local completed, integrated or uncertain recovery history. Replacing ready with working is idempotent even when working is already present. No ready label is restored and no preserved workspace is reused by this path. Preserved Codex and integration recovery retain their separate existing protocols.
