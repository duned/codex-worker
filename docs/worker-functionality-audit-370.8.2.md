# Worker functionality audit (370.8.2 / #454)

## Scope and disposition

This is a source and contract audit of the Worker product in the current checkout, with bounded corrections to project configuration administration. It is not a live GitHub/Codex, real-node provisioning, deployment or release campaign. The table inventories the discovered product areas; “retain” means no change justified by this review, not proof that every possible failure has been exercised. Existing tests cited below are coverage references, not claims that those tests ran during this audit.

Server remains the control plane. Worker history, identity, cached configuration and recovery resources remain operational state. Shared node/protocol behavior stays in `src/Shared` (`CodexProvisioning`). No Server store, alternative scheduler, protocol version or product version was introduced.

## Confirmed corrections

1. **An active checkout could change by case alone on Linux.** Both `ProjectConfigurationService.MutateAsync` and `ProjectRuntimeRegistry.ReplaceConfiguration` compared checkout paths with `OrdinalIgnoreCase`. `/.../checkout-alpha` and `/.../CHECKOUT-alpha` could therefore pass the “same execution identity” guard while referring to different directories. The service could persist the replacement during an active execution; the registry could accept the replacement during an active reservation. The shared predicate now uses ordinal paths on non-Windows and ignores case on Windows, matching the existing execution/Git path comparison convention. GitHub repository identifiers retain their case-insensitive comparison. This also removes the duplicated repository/checkout predicate from the service.
2. **YAML deletion confinement accepted a case-distinct sibling.** `LocalYamlProjectConfigurationProvider.RemoveAsync` compared the parent directory without case sensitivity on every OS. A caller supplying a path in sibling `PROJECTS` could pass confinement for configured `projects` on Linux. The parent comparison now follows the platform convention before deletion. This is a lexical path boundary correction; it does not claim to solve symlink aliasing or change filesystem authorization.

Focused regression coverage added:

* Registry replacement with an active reservation rejects a case-only checkout change on non-Windows, preserves the old configuration and releases capacity normally; Windows keeps its existing case-insensitive behavior.
* Administration with active durable history rejects the case-only checkout change **before writing YAML**, even without a runtime registry attached.
* Provider deletion refuses a case-distinct sibling and preserves its contents, while deletion inside the configured directory still succeeds.

No recovery checks, ownership checks, retry bounds, validation commands, configuration keys, release metadata or protocol fields were removed or changed.

## End-to-end workflow traces and retained guarantees

**Startup to scheduling.** `Program` loads local/global configuration and enters `WorkerHost`. Managed startup registers/synchronizes or loads validated cached state for observation. Project startup performs read-only checkout validation, capability checks, label discovery/creation and initialization; isolated failures mark only that project unavailable. Agent authentication readiness remains a distinct gate before queue access. The host schedules only within global/per-project capacity and, in managed mode, synchronized configuration plus Server assignment authority. Registry reservations pin the expected configuration and track active capacity independently of when execution history is written.

**Claim to completion.** `Worker` selects/claims an Issue or accepts a managed assignment, records execution identity and creates an execution repository. `ExecutionRunner` owns preparation, implementation, validation and bounded repair. Structured task failures preserve useful changes and return a safe outcome; infrastructure or uncertain GitHub mutation failures retain reconciliation state. Integration takes the repository gate, checks cancellation/current authority, rebases against the authoritative base and validates that source. Durable integration/completion evidence precedes reporting and resource retirement. GitHub reporting and notification checkpoints prevent blind replay after interruption. Engine invocation never owns branch creation, commits, push or Issue lifecycle.

**Interruption to continuation.** Host shutdown cancels/joins children and lease work. Execution stage and durable validation state select the recovery protocol: interrupted implementation, standalone validation/integration continuation, integration conflict or uncertain completion. Recovery coordinators inspect history, attempt lineage, original settings, registered workspace/process ownership and Git identity. Managed recovery still needs an assignment/generation; local history or a cached snapshot cannot grant it. Unsupported, changed or ambiguous resources require inspection instead of automatic destruction or implementation replay.

**Maintenance to durable recording.** Standalone maintenance reserves a drain, waits for active work and selects bounded history. Managed maintenance validates command identity/generation and fresh Server authorization. Cleanup takes the repository gate, rereads history and checks Git ownership before mutation. Pending Codex, integration or reporting resources remain with their owning recovery protocol. Successful Git cleanup is followed by a narrow durable metadata write; partial failures are not recorded as success. Archive retains provenance and requires terminal/retention proof. Inspection is never reusable authorization to mutate later.

These layers are not duplicate checks: configuration validation concerns candidate shape/resources; reservations concern concurrent admission; leases concern current remote authority; Git inspection concerns actual retained resources. None can replace the others.

## Concrete follow-ups

* Review remaining case-insensitive **configuration file selection** in `ProjectConfigurationDiscovery.ValidateCandidate` and service removal/rename filters. Add manual case-distinct YAML filename coverage before changing filtering/uniqueness behavior. Keep this separate from the corrected active checkout and deletion guards.
* `ProjectConfigurationService.ReloadAsync` publishes reload rejection, and the watcher publishes another rejection after catching it. Consolidate event ownership with deterministic notification coordination coverage; avoid a timing-sensitive test that asserts one filesystem event per write.
* `WorkerHostResourceCollector` selects disks by raw string prefix. Cover mount `/app` versus application directory `/application`, and malformed/empty CPU input, through a small input seam before adjusting telemetry collection. Telemetry must stay optional and cancellation-aware.
* Review drain cancellation/readiness reporting (`WorkerLifecycle.CancelDrain` restores `ready` while host readiness is checked separately), and explicitly define the presentation contract for an unavailable node after cancelling a drain. Preserve host execution preflight regardless of the display decision.
* Review current integration conflict-resolution callbacks against the repository's policy on automatic conflict resolution. This audit leaves that established workflow unchanged; changing it needs explicit behavioral coverage and a clear policy decision, not deletion of a callback during a configuration fix.
