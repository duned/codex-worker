# Claude headless execution

CCC uses the same isolated Issue worktree, authoritative validation and bounded repair loop as Codex. Engine selection is durable and repairs never fall back to Codex. Existing repository verification, lease checks, integration and reporting remain Worker responsibilities. An interrupted or malformed Claude invocation is an infrastructure failure with uncertain workspace state; it is preserved for existing recovery inspection rather than automatically replayed.

The adapter requires Claude Code 2.1.259 or later and confirmation in the installed CLI help of every required security/output flag. Unsupported installations fail closed. It invokes the service account's native executable with that account's HOME and the execution worktree as cwd, using argument lists, stdin for prompts, bounded output and the configured execution timeout. Cancellation terminates the child through the existing ProcessRunner.

The trusted boundary is vendor-supported `--restricted` file-tool confinement, combined with `--safe-mode`, disabled hooks, an empty strict MCP configuration, a file-only tool list and `dontAsk` / `--permission-prompts none`. No Bash, command runner, subagent, browser or network tool is enabled. Git metadata writes are denied. This intentionally means Claude cannot run local shell validation: the Worker runs the configured commands and sends redacted failures back for repairs. No unrestricted permission bypass is used. Service administrators and managed Claude policy remain trusted; repositories cannot supply executable hooks/plugins/settings to this invocation. Deployments unable to trust the vendor file-tool boundary must leave CCC unavailable rather than grant additional tools.

GitHub environment credentials and normal Git credential helpers are stripped using the existing child environment boundary. Claude-specific inherited configuration overrides are removed. CLI stderr, rejected-result payloads and exception details are not persisted. Structured outcomes use the existing normalized contract and diagnostic redactor. Project instructions and repository AGENTS.md are explicitly included; native CLAUDE.md/customization loading is disabled. The Worker owns Git commits, integration, push and Issue lifecycle.

CLI flag semantics and restricted-mode requirements: [official CLI reference](https://code.claude.com/docs/en/cli-reference).
